Crank & CAM Signal Generator

A SystemC-based virtual signal generator project

Project Overview

This project models a virtual 60-2 crankshaft and a configurable CAM sensor signal generator using SystemC. It simulates engine rotation dynamics in real time, generating output signals and engine position data for use in virtual testing and signal analysis workflows.

Crank Signal

The crankshaft signal consists of 60 equally spaced teeth, but with 2 missing teeth (tooth indices 58 and 59) to allow synchronization and engine position detection. Each crank tooth represents 6 degrees of crank angle.

The crank signal is derived from two main inputs:

  • RPM – Defines the target engine speed in revolutions per minute
  • Acceleration – Determines how quickly the engine ramps up or down to the target RPM
Using these, the simulator computes the time between teeth (tooth time) and applies a gap during the missing teeth. This allows downstream systems to align the signal with actual engine revolutions.

CAM Signal

The CAMshaft rotates at half the speed of the crankshaft and contains fewer features. The signal is generated based on a user-defined pattern of alternating high/low signal levels and their durations (in degrees).

For example, a pattern like {15, 15, 75, 15, 75, 75, 15, 75} means the CAM signal:

  • Starts high for 15 degrees
  • Goes low for 15 degrees
  • High for 75 degrees
  • Low for 15, and so on...
This pattern is repeated over a full 720-degree crank rotation, and each segment aligns with crank angle degrees for accurate synchronization.

Synchronization and Detection

To determine engine phase, the CAM pattern includes a unique synchronization pulse, usually a 15/15 high-low pair. A dedicated module, the CamSyncDetector, monitors signal transitions and pulse widths to detect this signature event, which indicates the beginning of a new engine cycle.

Engine Position Tracking

As the crank signal progresses, an angle_deg value is continuously published to represent the current crankshaft angle in the range 0 - 720 degrees. This allows the CAM module and other peripherals to react accordingly to real engine timing.

Use Cases

  • Virtual signal testing for ECUs without physical hardware
  • Debugging software that relies on crank/CAM input
  • Validating synchronization logic
