IMAGE QUALITY ANNOTATION - ORGANIZER NOTES

Manually assigned image groups
Put your selected images in these folders under the website:
  annotation/groups/group-01/
  annotation/groups/group-02/
  annotation/groups/group-03/

Additional numbered folders such as group-04 and group-05 are discovered automatically.
Each group may contain any number of images, including zero. There is no fixed
quota, automatic split or imposed overlap. Put an identical copy in multiple
folders wherever you want overlap. Content hashes identify the same image across
groups even when renamed. Duplicate copies within a group are shown only once.
Visually identical re-encoded images require manual deduplication.

Refresh after adding/removing images
From the website root:
  python annotation/prepare_dataset.py

A static site cannot enumerate server folders itself. This command scans the
numbered folders and refreshes the browser's image list. No counts or code edits
are required. Redeploy generated data with the website for hosted changes.
Files are ordered by their path within the group. Nested folders are scanned.
Supported: JPG, JPEG, PNG, WebP, GIF and BMP, case insensitive. Check that animated
GIFs are suitable for your still-image task.

The page displays actual counts. Empty groups cannot be started. Navigation,
progress, completion and exports use the selected group's length. Direct links:
  /annotation/?group=group-01
  /annotation/?group=group-02
  /annotation/?group=group-03

Generated data
The script copies images under annotation/data/images with neutral names and
generates annotation/data/dataset.json. Original source images are unchanged.
Removing an image from a group removes it from the refreshed list. Older generated
copies remain on disk but are no longer displayed unless still assigned.
The private organizer report goes into ../annotation-organizer relative to the
website root. It records source paths, actual counts and overlap. There is no
automatic assignment of people or internal/external roles. Assign group links
and anonymous annotator codes yourself. Multiple people can label a group with
different codes. Additional people mean additional independent judgments.

Original group folders inside the site may be accessible if deployed. To keep
source folders outside the site, use an external parent folder with numbered group folders, and pass --source:
  python annotation/prepare_dataset.py --source "C:\path\to\groups" --private-report-dir "C:\path\outside-site\organizer" --manifest "C:\path\to\manifest.csv"

Repeat --manifest for multiple collector manifests. SHA-256 matching preserves
attribution after renames. Edited/re-encoded images need separate attribution.
annotation/data/ATTRIBUTION.csv retains known attribution on later refreshes
without manifest arguments. Resolve missing attribution before public sharing.

Finalize the study
Edit study.json to set contact, return_instructions, final label definitions and
guidelines_version. Add at least one reviewed image example per label under
annotation/examples. Example study.json entry (in the examples array):
  {"src":"examples/example-01.jpg","explanation":"Lens contamination and Usable: two droplets affect the edge while the main scene stays clear."}
Retain example attributions and keep examples outside the evaluation groups.
The current written examples are illustrative, not reviewed photo examples.

Run the refresh command after changing guidelines: the dataset embeds a frozen
study.json snapshot. Identical refreshes keep the study ID and saved progress.
Changes to images, group membership, order or guidelines create a new study ID,
so old answers are not silently reused on a different task. Finalize before
students start; keep exported results before revising an active study.

Preview locally
From the website root, run .\start_annotation.ps1 or:
  python serve_annotation.py --port 8000
Open http://127.0.0.1:8000/annotation/
Use a web server, not a double-clicked HTML file. The refresh command does not
deploy the site. The website includes a Vercel submission API. Configure its GitHub token as
described in ONLINE_SUBMISSION_SETUP.txt. Drafts remain browser-local.

Student workflow (also on the page)
1. Read the guide and reviewed examples. Enter the assigned anonymous code and
   select the assigned group.
2. Inspect each image; enlarge when helpful. Select every visible artifact, or
   explicitly choose no listed artifact / unsure.
3. Apply all visible labels: Physical Obstruction, Exposure Fault, Lens
   Contamination, Optical/Motion Blur, and Lens Fog / Condensation. Even small
   defects count. Use Acceptable / unsure when appropriate.
4. Selections save automatically as you click. Next moves to the next image.
   Previous and the image selector let you review answers.
5. Click Submit annotations after every image has an answer. Wait for confirmation.
   Download backup saves a JSON copy at any time. Progress is also saved
   in the same browser when storage works. Resume with the same code/group.
   CSV is an optional readable copy; downloaded files cannot be imported.
6. A successful online submission sends the JSON directly to the organizer's
   repository and closes the group. Downloading a backup alone is not submission.

Output and analysis
JSON and CSV include filename, the original name from that image's group folder,
alongside the stable image ID. This metadata does not reset existing progress.
JSON stores study, annotator, group and stable image IDs. Each answer contains
a labels array, artifact_judgment, status and
approximate active_seconds. CSV uses | between multiple labels. Drafts, pending
items are not negative labels. JSON is the results format.
Join dataset_id + image_id across DIFFERENT annotator codes for agreement.
Multiple exports by one person are versions, not additional votes. The private
report lists images shared by any groups and those shared by all three. Keep
individual judgments; no automatic consensus/ground-truth labels are produced.
Time an internal pilot to estimate the workload for your chosen group sizes.

ADDING A NEW LOCAL IMAGE COLLECTION (OFFLINE)
Install the local image-preparation tools in your Python environment:
  python -m pip install -r annotation/requirements-images.txt
Preview an assignment plan without changing the website:
  python annotation/add_image_groups.py --source "C:\Users\moham\Downloads\image_test\collected_images"
Create the planned groups and then refresh the website manifest:
  python annotation/add_image_groups.py --source "C:\Users\moham\Downloads\image_test\collected_images" --apply
  python annotation/prepare_dataset.py

The default is up to 50 images per new group, with 10 randomly selected common
images in every new group. Remaining images occur in only one new group; the last
group can be smaller. Seed 20261029 makes the random selection reproducible.
Change --group-size, --shared, or --seed for a future batch if desired.

Original SHA-256 hashes exclude images already assigned to existing groups even
when incoming files were renamed. Exact duplicate source files are counted once.
Existing groups are preserved. New group numbering starts after the highest
existing numbered folder. Running the same collection again adds no groups.

Source images stay in the input folder. The website receives WebP display copies
with the long edge at most 1600 pixels and quality 95. Orientation is applied and
ICC color profiles are retained when supported. HEIC and AVIF are decoded through
the image-preparation tools. Multi-image inputs, including JPEG/MPO photos with additional image frames,
use their primary frame. Source frame counts and formats are recorded for review.

Each generated group contains .image_sources.json. Keep this file with the group:
it maps the WebP copy to the ORIGINAL image ID and original filename. The normal
preparation command verifies the copy hash before trusting that identity. Changing
a web image without updating its provenance is rejected, preventing labels being
attached to the wrong source. A private preparation report outside the website
records original paths, overlap, conversion settings and display/source hashes.

The public manifest and submitted annotation JSON retain display metadata so model
preparation can distinguish source originals from the images actually presented to
annotators. Changing a group's display version changes its completion fingerprint.
Earlier groups without web-copy provenance keep their existing fingerprints and
completion status. Commit the new group folders, their provenance files, generated
annotation/data, and the updated preparation/API code together before deploying.
